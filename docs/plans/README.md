# 实施计划目录（Implementation Plans）

`docs/plans/` 存放**多 PR / 多阶段变更的实施计划**：把一个已定稿的设计
（`docs/design/`）拆成可独立合并的 PR 序列，并跟踪每步状态。

## 何时需要计划文档

- 一个 design 落地需要 **多个 PR**（例如跨模块重构、契约迁移）。
- 需要分阶段推进、每阶段单独验证的变更（例如先加测试基线再动实现）。

单 PR 可完成的工作**不需要**计划——design 文档或 issue 的验收标准已足够。

## 文件命名与结构

- 命名：`YYYY-MM-DD-<kebab-case-topic>.md`（日期 = 创建日期）。
- 计划文档（本仓库当前以中文撰写；若涉及国际协作可按 design 的双语规则成对）。
- 模板：[plan-template.md](plan-template.md)。

## 硬性规则

1. **每个 PR 步骤独立可用**：可编译、`mvn verify` 全绿、不留"主干中间态不可用"。
2. **PR 序列顺序即依赖顺序**：后一步只依赖已合并的前几步。
3. **状态实时更新**：每步落地后把状态改为 `Done（PR #N）`；计划偏离时在文档里
   记录原因，而不是让文档悄悄过期。
4. 计划完成（全部 Done）后，把对应 design 的 status 改为 `Implemented`。
